Parte I — Questões teóricas (90 minutos)
Bloco A — Fundamentos de POO
1. Explique a diferença entre classe e objeto. Apresente um exemplo de cada um em um sistema acadêmico.
R - Classe seria a ficha de um personagem ou de itens, enquanto objeto seria o machado, a espada e o arco. Em forma prática, um cria a ficha e o outro a existência. 
2. O que são atributos e métodos? Diferencie estado e comportamento de um objeto.
R - Em jogo de RPG, o atributo seria as características ou variáveis da classe, como: nome, vida, mana, nível e os métodos seriam as ações, como atacar, curar. Um é sobre como são suas informações e o outro faz as ações dessa classe. 
3. Qual é a função de new? Diferencie criar um objeto e declarar uma referência.
R - Para aquele objeto existir, precisa ter um espaço, "new" faz ele ocupar um pouco da ram na hora da execução. 
4. Explique encapsulamento. Por que evitar atributos públicos sem necessidade?
R - Se ela estiver pública, qualquer alteração pode ser feita nas classes sem métodos; ela privada só poderá alterar utilizando dois métodos, como: getters e setters.
5. Qual é a finalidade do construtor? Explique o uso de this.
R - O construtor serve para que o objeto inicie com todas as características. O “this”' seria sua definição de existência no código. 
Bloco B — Relacionamentos e herança
6. Diferencie associação, agregação e composição; exemplifique.
R - Associação: as classes genéricas onde qualquer objeto pode usar sem ter apropriação própria. Agregação: um objeto pode ter outro objeto genérico, onde necessariamente não é dele, pois continua a existir mesmo com a exclusão do objeto por cima. Composição: seria um objeto ligado, onde ele só existe se o objeto pai existe 
  

7. O que é ArrayList e quando preferi-lo a um vetor de tamanho fixo?
R -A rrayList é volátil (dinâmico), pois altera de tamanho conforme a adição ou remoção de objetos. Precisamos de um tamanho definido para definirmos um vetor fixo 
8. Diferencie superclasse e subclasse. Explique extends e super
.R - A superclasse seria uma classe principal genérica, como todos os personagens de um jogo, enquanto a subclasse herda tudo da superclasse, mas com suas adições de características próprias
9. Diferencie sobrecarga e sobrescrita de métodos; dê exemplos.
R - Sobrecarga cria variações de uma ação dentro do próprio objeto, como: lugar, características e funções, enquanto a sobrescrita altera o comportamento através de herança.
10. O que é polimorfismo? Como uma referência de superclasse aponta para objetos de subclasses?
R - Ao invés de usar o objeto com todas as suas subclasses, podemos usar classes específicas para uma determinada tarefa.
Bloco C — Interfaces e projeto
11. O que é interface? Diferencie implements e extends nos exemplos estudados.
R - A interface é o que define o que as classes farão, mas sem dizer como será feito. Extends: uma classe filha (dependente) herda de uma classe mãe (independente). Implements: uma classe decide adotar regras de uma interface e, com essas regras, ela conseguirá realizar novas ações. . 
12. Compare herança e composição. Quando a composição é preferível?
R - Herança é quando uma classe filha 'é uma' extensão da classe mãe, dependendo dela para existir. Composição é quando uma classe 'tem um' objeto dentro dela, funcionando de forma independente. A composição é preferível para evitar que alterações na classe mãe quebrem o código inteiro e para podermos mudar as características do objeto no meio da execução. 
13. O que é baixo acoplamento? Como a injeção por construtor ajuda?
R - Baixo acoplamento é o nível de independência das classes no código, onde uma não precisa saber como a outra funciona por dentro. A injeção por construtor ajuda entregando o objeto pronto na hora do 'new' da ficha, fazendo com que o personagem possa receber qualquer arma ou característica sem ficar preso a uma só.
14. Explique SRP, OCP e DIP com exemplos simples.
R - SRP significa que a ficha do personagem só cuida dos dados dele, deixando tarefas como salvar o jogo para outras classes. OCP permite adicionar novos heróis ou itens no jogo sem precisar mexer ou arriscar quebrar o código que já funciona. DIP faz o herói depender de uma interface genérica de arma, permitindo que ele equipe qualquer item sem ficar preso a uma classe concreta.
Bloco D — Padrões de projeto
15. O que é um padrão de projeto? Por que evitar aplicá-lo indiscriminadamente?
R - Padrão de projeto soluciona um problema específico de lógica, agindo solo ou em conjunto com algumas classes. Ele não define as tecnologias ou o banco de dados, pois a sua ideia principal é primeiro entender o conceito do problema e depois fazer a estruturação desse conceito na lógica do código. 
16. Explique Singleton e a finalidade do construtor privado e de getInstancia().
R - Singleton seria um padrão de projeto onde uma classe teria somente um objeto rodando na ram. Ficando global, qualquer classe poderia acessar. O construtor privado serve para trancar a porta de entrada da classe, onde não há acesso direto externo. 
17. Explique Factory Method e o papel dos criadores abstratos e concretos.
R - Factory Method serve para tirar o new do código principal e jogar para uma classe que só serve para fabricar objeto. O criador abstrato é só a regra dizendo o que a fábrica tem que fazer, e o criador concreto é a fábrica de verdade que dá o new na parada que você quer. 
18. Como Strategy organiza descontos comuns, estudantis e promocionais?
R  - Strategy faz com que cada cálculo vire uma classe independente, que assina a mesma interface.
19. Como Observer comunica um pedido confirmado a estoque, financeiro e auditoria?
R - Observer serve como um notificador de pedidos para alteração de estoque, envio para o financeiro ou monitoramento da auditoria, mudando as ações conforme o fluxo acontece. 
20. Diferencie Adapter e Facade; dê um caso de uso de cada um.
R - Adapter serve para conectar duas classes que usam códigos ou formatos totalmente incompatíveis, funcionando como um adaptador de tomada de viagem. Facade serve para esconder a bagunça de um sistema complexo e cheio de classes diferentes, criando uma interface simples com um botão só para resolver tudo de uma vez.
